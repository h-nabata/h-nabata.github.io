# 複数フラグメントAFIR

任意の非周期分子を読み込み、描画上で複数の原子団と人工力のペアを指定します。設定・人工項の確認・保存・表示はブラウザ内で処理し、探索時の物理エネルギーと力だけを、このPCの計算エンジンへ依頼します。外部の計算サーバーへ座標を送信しません。

## 操作

1. 分子を読み込み、未適用の座標編集を反映します。「AFIR / 原子団に人工力」を開きます。
2. 原子をクリックして複数選択するか、右ドラッグで範囲を選び、名前を付けて「選択を登録」を押します。各原子団は色付きの輪で表示されます。登録済みの名前を押すと、その原子団を選択し直せます。
3. 原子団A/B、「近づける／離す」、γを指定して「ペアを追加」を押します。複数ペアを同時に適用できます。同一ペア内の原子重複や、A/Bを逆にした同じペアの二重登録は拒否します。異なるペアでの原子団共有は可能です。
4. 全電荷・スピン多重度・探索予算・収束しきい値を確認します。「人工項を確認」では、物理ポテンシャルを呼ばず、座標を変えずに人工項だけを評価します。
5. 「このPCの計算エンジンに接続」でNEBと共通の接続画面を開きます。[ローカルサービス](./local-engine/README.md)を起動し、URLと起動時のTokenを入力して接続します。AFIRにはbridge.py 1.1.0が必要です。接続後にダイアログを閉じ、AFIRパネルで探索を開始します。
6. 結果を確認してJSONを保存します。「構造列を適用・再生」でFRAMESへ反映し、スライダーや再生ボタンで軌跡を確認します。計算前の構造はUndoで復元できます。入力の結合表は保持するため、形成・切断の判定は座標から別途確認してください。

入力JSONにはXYZ、永続的な原子ID、原子団、ペア、計算条件、`enb-general-afir/1`形式のPython用設定を含めます。Python側で使用する場合は`xyz`を`input.xyz`、`pythonConfig`を`config.json`として保存します。`indices`はそのXYZの1始まりの原子番号です。通常のプロジェクト保存では`metadata.afir`に設定が残ります。接続Tokenは保存しません。

## 人工項と計算条件

各ペアについて、`D = Σ(w_ij r_ij) / Σw_ij`、`w_ij = ((R_i + R_j) / r_ij)^6`を使い、物理エネルギーに`ρ α D`を加えます。ρは引力で+1、斥力で−1です。重みの座標依存性も微分した解析力を用い、ペアごとに正規化した人工項を足し合わせます。

γはkJ/mol単位の衝突エネルギーの尺度で、障壁の上限を保証する値ではありません。Arの基準値`R0 = 3.8164 Å`、`ε = 1.0061 kJ/mol`から次式でαへ換算します。

```text
α = γ / { R0 [ 2^(-1/6) − (1 + sqrt(1 + γ/ε))^(-1/6) ] }
```

式中のγとεは同じエネルギー単位を使い、出力αをeV/Åへ変換します。γ=100 kJ/molではα≈1.231378 eV/Åです。γ=0は、この実装では人工項を解除する明示的な規約です。原子半径はASE 3.26.0のCordero共有結合半径です。プレースホルダー半径を避けるためAFIR入力はH〜Cmに限定します。

初版は非周期・固定電荷・固定スピン、2〜500原子、2〜64原子団、1〜128ペア、最大500ステップです。g-xTBまたはtbliteでエネルギー・力を計算し、FIREで人工項を加えたポテンシャルを最適化します。既定は150ステップ、最大変位0.04 Å、最大有効力0.05 eV/Å。UIの「収束」は人工力下の収束を意味します。g-xTBとGFN系は明示的に区別し、失敗時の自動切替は行いません。

[MaedaらのAFIR論文](https://doi.org/10.1002/jcc.25106)の人工項を使った独立実装です。GRRM全体の再実装や、反応の網羅性を保証するものではありません。生成物・TSの確定には、人工力を外した経路緩和、TS最適化、振動解析、接続確認が必要です。これらの検証をAFIR探索の完了として自動認定しません。

## 保存・停止・再開

結果は`molecule-afir-trajectory/1`で、全フレームの座標、原子ID、物理エネルギー・力、人工項、合計エネルギー、最大有効力、収束状態、計算条件のハッシュを保持します。物理エネルギーと人工項を混ぜて障壁と表示しません。計算開始後に構造・設定が変わった場合、結果による上書きを拒否します。

中止・時間切れ・計算エラーでは子プロセスを停止し、受領済みの評価済みフレームを暫定結果として返します。結果JSONを保存してください。サービスのメモリ上の結果はサービス終了で消えるため、ディスクの恒久チェックポイントとは異なります。途中フレームをプロジェクトへ適用して保存すれば、その構造から新しいAFIR探索を開始できます。FIREの内部状態まで復元する再開ではありません。ブラウザを閉じる前に中止・保存し、使用後は端末でCtrl+Cを押してサービスを終了します。

## 開発者向け

- `afir.js`: IDでの原子団解決、入力検証、Ar換算、人工エネルギー・力、入力エクスポート。ネットワーク処理なし。
- `afir-ui.js`: 選択・配色・条件・結果表示・Undo。計算開始時には、入力欄の未確定編集も読み取る。
- `afir-runner.js`: NEBと共通のlocalhost限定クライアント。全フレームの原子対応・単位・人工項を検証してから適用する。
- `local-engine/bridge.py`: 物理計算、AFIR/FIRE、原子ID検証、停止と途中結果。127.0.0.1のみで待受け、Token・Host・Originを検証する。
- `afir-search.js`: 同じ数学仕様のブラウザ用最適化器。物理ポテンシャル評価器を注入するAPIを持つが、g-xTB/UMAのブラウザ実装を含まない。公開UIは検証済みのローカルサービス経路を使う。

人工項・Ar定数・半径・データ形式を変更する場合は`afir.test.cjs`、`afir-search.test.cjs`、`test_afir_engine.py`を再実行し、JSとPythonのエネルギー・力の一致を検証します。選択や保存形式を変更する場合は`ui.test.cjs`と`engine-browser.cjs`を再実行します。エンジンや単位の変更には実g-xTBの有限差分試験が必要です。

検証記録は[AFIR-VALIDATION.md](./AFIR-VALIDATION.md)を参照してください。
